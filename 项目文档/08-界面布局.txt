===============================================================
  魅魔杀 - 界面布局规则
  交接对象：DeepSeek 重制
===============================================================

【一、视口与尺寸】

1. 主视觉基线：1280x720 横屏
2. 只做横屏优先，不做独立竖屏分支
3. 不添加竖屏、仅触摸、虚拟键盘或窄设备专用分支
4. html、body、.game-shell 必须适配当前动态视口，不设固定最小宽高
5. 使用 100vh 兜底和 100dvh 主规则：
   css: height: 100vh; height: 100dvh;
6. 根使用 safe-area padding
7. viewport meta 必须包含：
   width=device-width, initial-scale=1, viewport-fit=cover,
   interactive-widget=resizes-content, user-scalable=no

【二、滚动规则】

1. html/body 不出现文档级滚动条
2. 长内容只在所属面板内部滚动
3. flex 列布局的滚动子项必须设置 min-height: 0
   （这是最高频布局bug：不加 min-height:0 会导致内容撑爆容器）
4. 内部滚动区域使用 overscroll-behavior: contain
5. 全局禁止弹性滚动穿透

css 骨架：
  * { box-sizing: border-box; }
  html, body {
    margin: 0;
    height: 100vh;
    height: 100dvh;
    overflow: hidden;
    overscroll-behavior: none;
    user-select: none;
    -webkit-user-select: none;
  }
  body {
    display: flex;
    flex-direction: column;
    padding: env(safe-area-inset-top) env(safe-area-inset-right)
             env(safe-area-inset-bottom) env(safe-area-inset-left);
  }
  .scroll-area {
    flex: 1;
    min-height: 0;
    overflow-y: auto;
    overscroll-behavior: contain;
  }

【三、iframe 尺寸变化处理】

iframe 尺寸会因以下事件变化：
- 进入/退出全屏
- 玩家旋转手机
- 移动浏览器地址栏收起
- 虚拟键盘弹出/收起

不能只在 DOMContentLoaded 时计算一次。
必须监听 resize 并重新计算布局。

Canvas 游戏特别要求：
- 尺寸变化时重置 canvas + 重绘
- 使用 devicePixelRatio 防止高DPI屏模糊
- canvas.width = canvas.clientWidth * dpr
- canvas.height = canvas.clientHeight * dpr
- ctx.setTransform(dpr, 0, 0, dpr, 0, 0)

DOM 游戏使用 ResizeObserver 比 resize 事件更可靠。

不要缓存初始化时的 innerWidth/innerHeight 作为常量。

【四、安全区】

进入全屏后 iframe 顶到屏幕边缘（刘海、底部home indicator、Android导航条）。
HUD/关闭按钮/主菜单必须加 safe-area 内边距：

  .hud-top { padding-top: env(safe-area-inset-top); }
  .hud-bottom { padding-bottom: env(safe-area-inset-bottom); }

viewport meta 必须写 viewport-fit=cover，否则 env(safe-area-inset-*) 全是 0。

【五、移动端适配（虽然横屏优先）】

- 触摸事件优先于鼠标事件：使用 pointerdown/pointerup 同时兼容
- 避免 mousedown + touchstart 双绑导致重复触发
- 按钮和可点击区域至少 44x44px
- 避免依赖 hover 效果，改用 :active 做按下反馈
- 帧率敏感的拖拽用 requestAnimationFrame 节流，不在 pointermove 里直接改DOM
- 文字游戏例外：正文容器允许 user-select: text

【六、触控行为】

  canvas, .play-area { touch-action: none; }
  body { user-select: none; -webkit-user-select: none; }
  .scroll-area { overscroll-behavior: contain; }

Canvas/拖拽/手势类游戏禁止默认触摸手势（下拉刷新、双指缩放、横滑返回）。
整页禁止文字选择（避免长按选中游戏UI文字弹放大镜）。

【七、虚拟键盘】

聊天/取名/答题输入框获焦时手机虚拟键盘压缩可视区域。
viewport meta 启用 interactive-widget=resizes-content 让键盘参与layout收缩。
配合 100dvh 自动收缩，输入框自动可见。

【八、紧凑横屏窗口】

紧凑横屏窗口减少间距和媒体尺寸，不切换到竖屏或仅触摸布局。
使用基于高度的紧凑规则，Pointer Events 对桌面鼠标拖拽仍然有效。

【九、标准大厅壳】

顶部栏三段式：
- 左：大"魅魔杀"标题牌和副标题"魅魔卡牌战斗 · 据点经营"
- 中：莉莉丝元、精华宝珠、饰品 分别计数
- 右：构建版本和圆形设置按钮

底部导航三等分命令：殿堂、客厅、熔炉
活动目的地使用深红填充、金色边框和金色下划线。

大厅模态内容位于固定顶部和底部壳之间。
模态或全局覆盖层活动时背景控件变为inert。

副本和战斗隐藏底部导航。战斗还隐藏顶部栏以最大化战斗面。

【十、字体与信息层级】

- 标题类型保留给"魅魔杀"、主要场景名和胜利
- 模态和页面标题使用金色；正常文本骨白；次要文本灰紫
- 密集卡牌保持名称和属性紧凑
- 字间距为0
- 竖排文字仅用于三个角色信息标签

【十一、表面与几何】

- 标准按钮和重复卡片使用 4px-8px 圆角
- 大型叙事、图鉴、信息和确认覆盖层可使用 18px-32px 圆角
- 主面板使用深色半透明填充、1像素金色边框、内嵌深红光和深黑阴影
- 悬停增加边框对比和内红光，不改变布局
- 激活状态使用深红填充+金色轮廓
- 选择使用更亮的粉色或金色外发光
- 禁用状态降低不透明度、移除发光、常应用灰度、保持标签可读
- 破坏性操作使用更深的红色
- 中性取消/返回使用炭灰色 ghost 样式
- 魅魔牌背在设置、确认、存档和模态表面中作为低透明度装饰水印

【十二、动画规则】

- 模态进入是短淡入和缩放/滑动，约 160-320ms
- 标准战斗立绘待机时保持静态
- 专属皮肤保留其设计的立绘、光环、场效、烟雾和皇冠待机循环
- 活跃单位身份仍使用现有的深红和金色轮廓和发光
- 入场、技能、受击、状态和胜利反馈可在有界时动画
- 手牌选择提升变更的卡片，不移动周围卡片
- 已选卡片在重渲染时保持稳定，只有新选/取消选择的卡片动画
- 角色、媒体、模态、战斗日志和定时字幕动画在重渲染时保持进度
- 减少动态偏好禁用重复选择和响应脉冲
- 游戏结算顺序绝不完全依赖动画支持

【十三、布局自检清单】

每写完一个布局检查：
1. 预览面板拉到最小/最大，body 不出滚动条
2. 长内容只在内部容器滚动，HUD 不跟着滚
3. 全屏按钮，UI 没有错位、内容没被截断、HUD 没压在刘海下
4. 切换设备预设，横屏布局不破
5. Canvas 游戏 resize 后还能正确渲染（不模糊、不拉伸、不被裁切）
6. 有输入框时键盘弹出，输入框保持可见

【十四、媒体元素约束】

- 媒体 src 只能绑定真实相对资源、可信HTTP URL、data URL 或 blob URL
- 文本内容不能先绑定到 <img src> 再用 CSS 隐藏
- 先判断类型再创建媒体元素，禁止先创建再隐藏
- 同一对象重渲染时保留已有媒体 DOM 和动画进度
- 卡牌移动显示完整牌面；隐藏信息使用牌背
- 音效区分飞牌、伤害、掉血、治疗、护甲和胜利
