# 魅魔杀：DeepSeek 重制交接包

本目录是给无法上传原始仓库文件的重制模型使用的项目说明。目标是让模型仅凭这些 Markdown 文档，理解产品定位、核心规则、正式内容、界面结构、静态运行环境和开发边界。

## 文档顺序

1. `01-project-overview.md`：产品定位、核心循环、资源、流程和完成范围。
2. `02-characters.md`：正式可用角色、属性、定位和技能。
3. `03-cards-and-relics.md`：卡牌、状态牌、饰品和牌堆规则。
4. `04-enemies-and-dungeons.md`：已完成怪物、Boss、正式副本和地图规则。
5. `05-battle-rules.md`：回合、攻击、响应、伤害、AI、结算和存档规则。
6. `06-ui-and-visual.md`：页面、UI、交互、视觉、动画和音频要求。
7. `07-architecture-and-dzmm.md`：纯前端架构、文件组织和 DZMM SDK 约束。
8. `08-qa-and-scope.md`：验收标准、已知风险、明确排除项和重制建议。

## 重制原则

- 这是一个静态 HTML/CSS/JavaScript 横版游戏，不需要服务器。
- 正式内容以本交接包为准；不要擅自加入新副本、亚缇娜、玛利亚或其他未完成内容。
- 数值、规则和名称必须保持一致；可以重写代码和视觉，但不能悄悄改玩法。
- 所有玩家可见名称使用中文正式名称，牌名使用 `【】`，标记使用 `“”`。
- 游戏标题为 `魅魔杀`，副标题为 `魅魔卡牌战斗 · 据点经营`。

## 原项目排除内容

- 不重制“新副本”及其专属剧情、地图、奖励和怪物，除非用户之后单独确认。
- 不重制未完成新增角色：`亚缇娜`、`玛利亚`。
- `索尼娅`、`橘千樱`、`格尔达`、`星野依`、`星野海一`已经属于正式角色范围；不要因为它们位于 future/new 数据文件就自动排除。
- 不把开发工具、测试代码、内部提交记录、作者密钥或原仓库文件路径当作玩家功能。
