### 4. 构建链路风险:未压缩 bundle 的可用边界(细化第 2 条警告)

- **摘要**:为避免后续会话(含容器/协作 AI)误用 AI 协助环境生成的**未压缩 bundle**,明确其可用边界与被拦截的确切环节。**本条为第 2 条中"不可用于发布"的完整依据。**
- **结论(三场景分离)**:

  | 场景 | 未压缩 bundle | 依据 |
  |:--|:--|:--|
  | 浏览器直接打开(本地 `publish/index.html` 或线上部署) | ✅ **可正常运行** | 即普通 JS;11 个文件均已 `node --check` 通过,与 terser 版逻辑等价 |
  | `git commit` | ❌ **被 pre-commit 拦截** | 见下 |
  | 正式发布 | ⚠️ 能跑但**不合规** | 项目规范要求 terser 产物 |

- **被拦截的确切位置**:`.githooks/pre-commit` 第一段即执行 `node tools/build-publish-bundles.js --check`。该模式会把**磁盘上的 bundle** 与 **terser 当场重新压缩的结果**逐字节比对;拼接产物必然不一致,抛 `Stale publish bundles: ...; run npm run build:bundles`,**提交被拒**。
- **体积不是被拦原因(已核实)**:未压缩合计 1.65 MB,压缩版约 1.11 MB,增幅约 +49%。但 `tools/check-asset-budget.js` 的 `singleFile: 2MB` / `criticalTotal: 2MB` 限制对象是 **`publish/assets/` 下的素材**,**不覆盖 `publish/bundles/`**。故 1.65 MB 不违反体积预算,卡点纯粹是 `--check` 的逐字节比对。
- **pre-commit 其余校验(一并注意)**:`--check` 之后依次还有 `check-static.js`、`check-resources.js`、`check-asset-budget.js`、`check-script-contracts.js`;且钩子**前置**要求 `src/original`、`publish` 下**无未暂存的改动、无未跟踪文件**,并校验 `publish/` 路径不含非 ASCII 字符与空格。
- **成因**:AI 协助环境(容器)无法访问 npm registry(403),装不了 `terser`,只能按 `tools/publish-bundles.json` 顺序做等价拼接。**此约束属环境限制,不属源码缺陷**,源码本身无任何问题。
- **行动规则(对后续所有会话/容器 AI)**:
  1. 需要**验证功能** → 可用未压缩 bundle 临时覆盖 `publish/bundles/` + `publish/index.html`,浏览器 `Ctrl+F5` 后实测,**允许**;
  2. 需要**提交或发布** → **必须**由本地执行 `npm run build:bundles` 生成 terser 压缩版,**禁止**把未压缩产物提交入库;
  3. 不得因"浏览器能跑"而误判产物合规——能跑 ≠ 能提交。
- **修改**:`docs/开发日记.md`(本条)
- **提交**:见仓库 `git log`(本次日记提交)。

### 5. 解决:容器环境内重新构建并压缩 bundle(撤除第 2/4 条中的"无法压缩"限制)

- **摘要**:此前判定"AI 协助环境无法压缩,只能出未压缩 bundle"**已不成立**。实测在容器内成功装配 **terser 5.49.0** 并跑通官方构建,产物经 `--check` 逐字节校验通过。**后续会话不应再以"装不了 terser"为由只出拼接产物。**
- **根因与解法**:npm registry 被墙(403)导致 `npm install` 不可用,但 **jsDelivr / unpkg 的 npm CDN 可直连**,可绕过 registry 直接取包文件。
- **可复现步骤(供后续会话/容器 AI 照做)**:
  1. **版本必须取自 `package-lock.json`,不可自选**:本项目锁定 `terser@5.49.0`、`acorn@8.17.0`、`@jridgewell/source-map@0.3.11`、`gen-mapping@0.3.13`、`resolve-uri@3.1.2`、`sourcemap-codec@1.5.5`、`trace-mapping@0.3.31`。版本不符则压缩字节不一致,`--check` 必失败。
  2. 取 terser 预构建 UMD 单文件:`https://cdn.jsdelivr.net/npm/terser@5.49.0/dist/bundle.min.js`,置于 `node_modules/terser/dist/`,并写 `package.json` 令 `main` 指向它。
  3. 用 `https://unpkg.com/<pkg>@<ver>/?meta` 列出包内真实文件,挑 `dist/*.umd.js`(或 `dist/*.js`)下载;terser bundle 的外部依赖只有 `@jridgewell/source-map` 与 `acorn`,前者再递归依赖 gen-mapping / resolve-uri / sourcemap-codec / trace-mapping。脚本见交付包 `tools/fetch_deps.py`。
  4. **构建需 git worktree**:`publish-build-version.js` 会 spawn `git` 校验版本。容器内须先 `git init` 并把**线上旧 bundle** 提交为 HEAD 基线,否则报 `Publish version checks require a Git worktree`。
- **推进版本号的三处(易漏!只改 index.html 会失败)**:
  1. `publish/index.html` 的 `meta[name=game-build]`(10 处 `v=` 一并替换);
  2. `publish/villa.css` 顶部 4 行 `@import url("./villa-*.css?v=<版本>")`;
  3. `publish/index.html` 里 build badge 的**显示文本**,格式为 `v26.0908.01`(与 `20260908-01` 不同,正则 `\\d{8}-\\d+` 匹配不到,**必须单独替换**)。
  以上任一遗漏,`check-script-contracts` 均报 `villa stylesheet imports must match` 或 `visible build badge must match` 并退出码 1。
- **实测结果**:11 个 bundle 全部生成,合计 **1.2 MB**(未压缩为 1.65 MB);`--check` 输出 `Publish bundles are current: ...` 退出码 0;`check-static`、`check-script-contracts` 通过。
- **容器侧局限(仍存在)**:`check-resources`、`check-asset-budget` 在容器内**必失败**,原因是容器只下载了 CSS/bundle、**未下载 `publish/assets/` 素材**(实测补下载缺失素材后 `check-asset-budget` 即转为通过)。**此二者失败与构建产物无关**,本地素材齐全时应正常通过,勿误判为构建缺陷。
