## ✅ 债务 1（已完成）：jscpd duplicate budget 超阈值（`duplicate budget` FAIL）

### 来源

`npm run check:core` 中的 `duplicate budget` 项，由 `tools/run-qa.js` 调用
`jscpd --config .jscpd.json` 驱动。

⚠️ 排查前必读：四个 lint 依赖（eslint / htmlhint / stylelint / jscpd）**默认不在仓库里**，
`node_modules/.bin` 下的软链指向已不存在的 `/mnt/lint`。
`run-qa.js` 遇到断链会以 `0.00s` 空转退出，**看起来像 FAIL，其实根本没检查**。
本条下面「2026-09-16 实测」那组数据，就是在依赖断链状态下采集的旧值。

沙盒中先跑 `source /data/workspace/setup-lint.sh` 装好依赖再采集（脚本幂等，
删掉软链后重跑可自恢复）。装依赖有两个坑，已写进记忆：

- `~/.npmrc` 含 `global=true`，npm 一律装到 `/usr/local/lib/node_modules`，需显式 `--prefix /mnt/lint`
- jscpd 5.x 还需平台二进制包 `jscpd-linux-x64-gnu`，入口是 `run-jscpd.js` 而非 `dist/cli.js`

### 现状（2026-09-25 重测：已达标）

采集命令（与 09-16 相同，但这次依赖是真的）：

```bash
source /data/workspace/setup-lint.sh
cd /data/workspace/repo
./node_modules/.bin/jscpd --config .jscpd.json --no-colors --no-tips
```

真实输出（节选）：


- **6 个 clone**，unique 重复行 **71**，占比 **0.20%**，阈值 **0.35%** → **通过**

  **2026-09-23** 增加了皮肤 FX 的 `ignore` 规则（已确认在远端，blob
  `d0ef7c5d62078d6f9a6568521eb06074e2e3c0ab`），把 9 个皮肤模板 clone（120 行）排除
- 复验：把 `ignore` 改回仅 `publish/bundles/**` 再跑 →
  **16 clone / 191 行 / 0.53%，EXIT=1**，与 09-16 记录吻合
  （印证当时那次测量确实没生效 ignore）

剩留的 6 个 clone（71 行）全为**非皮肤重复**，逐个读过源码，都能抽，但风险不一：

| clone | 位置 | 行数 | 抽法安全性 |
|:--|:--|--:|:--|
| 4 | `battle-manual-continuation.js` 36↔70（**同文件**） | 12 | 最安全，文件内抽函数即可 |
| 1 | `abe-mike-skills` ↔ `bondi-skills`（`discardRandom`） | 10 | 跨文件 |
| 2 | `abe-mike-skills` ↔ `ruins-grunt-skills`（反应队列） | 13 | 跨文件 |

| 5 | `bounty-ledger` ↔ `receipt-ledger`（`hash`/`legacyKey`） | 14 | ⚠️ 有坑 |

⚠️ clone 5 **不能直接合并**：两侧 `MAX_SEQUENCE` 不同
（一侧 `Number.MAX_SAFE_INTEGER`，另一侧 `1_000_000_000_000`），
照抄合并会引入真 BUG，必须参数化。

### 结论与处理（2026-09-25，用户选定「方案 A：关闭债务」）

验收命令全部通过，**债务关闭，不动代码**：

```bash

npm run check:core         # 9/9 PASS（duplicate budget 实跑 1.64s，非空转）
npm run lint               # 3/3 PASS
```

**未消除的部分与后续注意**：

1. **皮肤 FX 那 120 行重复仍然存在**，只是被 `ignore` 排除。按原判断，
   它们是「同一套皮肤特效模板」的必然相似，**不建议硬拆**
   （会伤可读性，且改一个皮肤易误伤其他）。
2. **`ignore` 是承重配置，不是临时白名单**。
   实测：仅恢复为 `publish/bundles/**` 即 EXIT=1（0.53% > 0.35%）。
   任何改动 `.jscpd.json` 的操作都必须重跑 `check:duplicates` 验证。
3. ⚠️ 旧版「修掉 73 行即可降到阈值、不必动皮肤 FX」的估算**已作废**：
   它按 clone 实例行数粗算，且分母口径用错。
   若移除皮肤 `ignore`，剩余 120 行按 Total 口径约 0.33%、按 javascript
   口径约 0.36%——**恰好卡在 0.35% 阈值两侧**，属临界且未实测，
   **不要据此承诺「修完非皮肤部分就能摘掉 ignore」**。
4. 附带提醒：jscpd 运行时报 `over threshold (0.3%)` 是 `toFixed` 的显示误差，
   生效阈值以 `.jscpd.json` 的 `0.35` 为准，别被提示语误导。

## ✅ 债务 2（已完成）：刺客胶衣转换牌未标 `_entityConversion`（实体牌判定口径不一致）

### 来源

`src/original/battle-card-active-relics-assassin.js` 的 `assassinLatex()`。

三个饰品主动技都用 `CardUtils.convertAs` 把**实体手牌**转换成另一张牌使用
（`魅魔钢叉 → 魅杀`、`鬼王扑克 → 战术牌`、`刺客胶衣 → 刺杀`），
转换产物带 `convertedFrom`、不带 `virtual`，本质是实体牌。

外神之眼 / 魅魔吸精术的实体牌判定在
`src/original/ruins-witherer-skills.js` 的 `isEntityCard()`，
对饰品转换牌额外认一个 `_entityConversion` 标记：

```js
&& (!card._skill || !!card._entityConversion);
```

**已标注**：魅魔钢叉、鬼王扑克（2026-09-24 按用户要求修正为「触发外神之眼」）。
**未标注**：刺客胶衣 —— 改造未完成，用户指示「先跳过，完善时补上」。

### 现状（2026-09-24 实测）

`tools/test-relic-virtual-guard.js` 第 6 项：

```
✅ 6. 饰品·刺客胶衣（convertAs 刺杀·待完善） 应不触发 | 实际=不触发
   | virtual=false _skill=true gen=null type=slash
```

即刺客胶衣当前按「技能效果」处理，打 1312 **不触发**外神之眼；
而魅魔钢叉、鬼王扑克**触发**。三者同属 `convertAs` 却口径不一致。

#### 补充：锁魂镰刀判定下的反向冲突（2026-09-24 补测）

上面说的是**外神之眼**口径。但**锁魂镰刀**用的是另一套判定，
`src/original/card-utils.js` 第 37 行：

```js
const isEntitySingleKill = card => isKillCard(card) && !card.virtual && isSingleTargetCard(card);
```

它**只看 `!virtual`，不看 `_skill`，也不看 `_entityConversion`**。
因此刺客胶衣产物的表现与外神之眼**正好相反**：

| 饰品转换牌 | 外神之眼 | 锁魂镰刀 |
|:--|:--|:--|
| 魅魔钢叉（已标 `_entityConversion`） | 触发 | 触发 |
| 鬼王扑克（已标，且是战术牌） | 触发 | 不触发（非杀牌） |
| **刺客胶衣（未标）** | **不触发** | **触发** ← 冲突 |

实测（`tools/test-soul-scythe-relic-conversion.js`）：

```
刺客胶衣产物: {"name":"刺杀","type":"slash","virtual":false,"convertedFrom":"闪","_skill":true,"_entityConversion":false}
   ↳ 实测锁魂镰刀 hits=2 e2=27 isEntitySingleKill=true
```

即刺客胶衣打持有锁魂镰刀的角色时，锁魂镰刀**会**被触发，
但打 1312 时外神之眼**不会**被触发 —— 同一张牌两套判定给相反结论。

对照组口径一致，无需处理：
`carlos-skills.js`【疯狂射击】`→ 机枪扫杀`、`guest-characters-skills.js`
【终焉鬼影斩】`→ 魔杀` 这两处 `convertAs` 产物**不带 `_skill`**，
两套判定都算实体牌，结论一致。
