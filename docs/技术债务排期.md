## 债务 1：jscpd duplicate budget 超阈值（`duplicate budget` FAIL）

### 来源

`npm run check:core` 中的 `duplicate budget` 项，由 `tools/run-qa.js` 调用
`jscpd --config .jscpd.json` 驱动。

⚠️ 注意：四个 lint 依赖（eslint / htmlhint / stylelint / jscpd）**默认不在仓库里**，
沙盒中需先跑 `/data/workspace/setup-lint.sh` 才能真跑。
依赖缺失时该项会以 `0.00s` 空转退出，**看起来像 FAIL，其实根本没检查**——
排查前务必先确认 jscpd 能否 `--version`。

### 现状（2026-09-16 实测）

采集命令：

```bash
source /data/workspace/setup-lint.sh            # 装 lint 依赖到 /mnt/lint
cd /data/workspace/repo
./node_modules/.bin/jscpd --config .jscpd.json --no-colors --no-tips
```

真实输出（节选）：

```
│ Format     │ Files analyzed │ Total lines │ Clones found │ Duplicated lines │
│ css        │ 27             │ 2614        │ 0            │ 0 (0.00%)        │
│ javascript │ 396            │ 32793       │ 16           │ 177 (0.54%)      │
│ Total:     │ 423            │ 35407       │ 16           │ 177 (0.50%)      │

Found 16 clones.
ERROR: jscpd found too many duplicates (0.5%) over threshold (0.3%)
EXIT=1
```

- **16 个 clone**，unique 重复行 **177**，占比 **0.50%**，阈值 **0.3%**
- 配置见 `.jscpd.json`：`minLines 8` / `minTokens 80` / `mode mild` / `threshold 0.35`
  （CLI 实际判定时报的是 0.3%，以运行时输出为准）
- **CSS 侧 0 clone**，问题全在 javascript

### clone 分类（16 个，按 clone 实例行数合计 193）

| 类别 | clone 数 | 行数 | 明细 |
|:--|--:|--:|:--|
| **皮肤 FX 模板互似** | 9 | **120** | `angelica-berserker-skin-fx` ×4（↔ bertis-queen / manny-gun / flora-sonic / elrana-fallen-physician）、`elrana-fallen-physician` ×4（↔ wendy-teacher / flora-sonic / manny-gun ×2）、`character-skin-fx` ↔ `wendy-teacher` |
| **同文件内重复** | 2 | **27** | `battle-manual-continuation.js` 38↔79（15 行）、27↔67（12 行） |
| **跨文件非皮肤** | 5 | **46** | `bounty-ledger`↔`receipt-ledger`(14)、`battle-card-active-relics-core`↔`witherer-relic-skills`(11)、`flora-skills`↔`flora-speed-assault`(11)、`abe-mike-skills`↔`bondi-skills`(10) |

### 修复建议

**优先修（合计约 73 行）**：同文件内重复 + 跨文件非皮肤。
这两类是真重复，抽公共函数即可，风险低。

**不建议硬拆**：皮肤 FX 那 120 行。
它们是「同一套皮肤特效模板」的必然相似，硬抽公共层会伤可读性、并加大改一个皮肤误伤其他的风险。

### 估算（**未验证，开工时需实测**）

当前 unique 重复行 177，阈值 0.3% 对应约 **106 行**（35407 × 0.3%）。
修掉优先部分（73 行）理论上可降到 ~104 行，刚好跨过阈值——
**即不必动皮肤 FX 模板**。

⚠️ 这是按「clone 实例行数」粗算，而 jscpd 统计的是「unique 重复行」，两者口径不同
（16 clone 实例合计 193 行，unique 只有 177）。
**实际能降多少必须跑一次才知道**，不要按此数字承诺。

如果优先部分修完仍超阈值，两个备选：
1. 把皮肤 FX 共性抽成 `skin-fx-common.js`（工作量大、需逐个回归皮肤特效）
2. 调 `.jscpd.json` 的 `threshold` 到 0.8% 并给皮肤 FX 目录加白名单（改动小，但等于放松约束）

### 验收标准

```bash
npm run check:duplicates     # exit 0
npm run check:core           # duplicate budget PASS
```

并且：修复后**不得**出现新的 lint FAIL（eslint / stylelint 需同时过）。

## 债务 2：刺客胶衣转换牌未标 `_entityConversion`（实体牌判定口径不一致）

### 来源

`src/original/battle-card-active-relics-assassin.js` 的 `assassinLatex()`。

三个饰品主动技都用 `CardUtils.convertAs` 把**实体手牌**转换成另一张牌使用
（`魅魔钢叉 → 魅杀`、`鬼王扑克 → 战术牌`、`刺客胶衣 → 刺杀`），
转换产物带 `convertedFrom`、不带 `virtual`，本质是实体牌。

外神之眼 / 魅魔吸精术的实体牌判定在
`src/original/ruins-witherer-skills.js` 的 `isEntityCard()`，
对饰品转换牌额外认一个 `_entityConversion` 标记：

```js
&& (!card._skill || !!card._entityConversion);
```

**已标注**：魅魔钢叉、鬼王扑克（2026-09-24 按用户要求修正为「触发外神之眼」）。
**未标注**：刺客胶衣 —— 改造未完成，用户指示「先跳过，完善时补上」。

### 现状（2026-09-24 实测）

`tools/test-relic-virtual-guard.js` 第 6 项：

```
✅ 6. 饰品·刺客胶衣（convertAs 刺杀·待完善） 应不触发 | 实际=不触发
   | virtual=false _skill=true gen=null type=slash
```

即刺客胶衣当前按「技能效果」处理，打 1312 **不触发**外神之眼；
而魅魔钢叉、鬼王扑克**触发**。三者同属 `convertAs` 却口径不一致。

#### 补充：锁魂镰刀判定下的反向冲突（2026-09-24 补测）

上面说的是**外神之眼**口径。但**锁魂镰刀**用的是另一套判定，
`src/original/card-utils.js` 第 37 行：

```js
const isEntitySingleKill = card => isKillCard(card) && !card.virtual && isSingleTargetCard(card);
```

它**只看 `!virtual`，不看 `_skill`，也不看 `_entityConversion`**。
因此刺客胶衣产物的表现与外神之眼**正好相反**：

| 饰品转换牌 | 外神之眼 | 锁魂镰刀 |
|:--|:--|:--|
| 魅魔钢叉（已标 `_entityConversion`） | 触发 | 触发 |
| 鬼王扑克（已标，且是战术牌） | 触发 | 不触发（非杀牌） |
| **刺客胶衣（未标）** | **不触发** | **触发** ← 冲突 |

实测（`tools/test-soul-scythe-relic-conversion.js`）：

```
刺客胶衣产物: {"name":"刺杀","type":"slash","virtual":false,"convertedFrom":"闪","_skill":true,"_entityConversion":false}
   ↳ 实测锁魂镰刀 hits=2 e2=27 isEntitySingleKill=true
```

即刺客胶衣打持有锁魂镰刀的角色时，锁魂镰刀**会**被触发，
但打 1312 时外神之眼**不会**被触发 —— 同一张牌两套判定给相反结论。

对照组口径一致，无需处理：
`carlos-skills.js`【疯狂射击】`→ 机枪扫杀`、`guest-characters-skills.js`
【终焉鬼影斩】`→ 魔杀` 这两处 `convertAs` 产物**不带 `_skill`**，
两套判定都算实体牌，结论一致。

### 分类

一次性补齐，风险低。

### 建议

在 `assassinLatex()` 的 `convertAs(...)` 产物上补一行
`_entityConversion: true`，删除源码里对应的
`TODO(刺客胶衣改造未完成)` 注释块，再把
`tools/test-relic-virtual-guard.js` 第 6 项期望值由 `false` 改为 `true`。

注意：**不要靠删掉 `_skill: true` 来实现**。
`_skill` 同时被伤害加成计算（`src/original/battle-combat-attack-values.js`
第 13 行 `card._skill ? 0`）等多处依赖，删除会直接改变伤害值。

### 验收标准

**补上标记后两套判定自动统一**：外神之眼由「不触发」变「触发」，
锁魂镰刀本来就是「触发」，冲突消除，无需改 `card-utils.js`。

```bash
node tools/test-relic-virtual-guard.js            # 10/10，第 6 项改为「应触发」
node tools/test-soul-scythe-relic-conversion.js   # 8/8，刺客胶衣 hits=2 仍成立
npm run check:bundles                             # 11/11 current
npm run test:logic                                # exit 0，FAIL 0
```
