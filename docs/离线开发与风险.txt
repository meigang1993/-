离线版开发建议

保持纯静态
使用 HTML + CSS + JavaScript + 本地图片/音频。
不依赖 Node、Python、Express、端口监听或后端服务。
入口固定为 publish/index.html。
为 SDK 缺失设计降级
离线环境中 window.dzmm 不存在。
AI 对话、AI 绘图、云端 KV、分享、创意工坊都要判断是否可用。
不可用时显示明确提示，并提供本地替代逻辑，不能白屏。
js


const onlineFeatures = Boolean(window.dzmm);

if (!onlineFeatures) {
  showMessage("当前为离线模式，AI 和云端存档不可用");
}
存档采用双模式
离线独立页面可以使用 localStorage。
Game Studio / 生产 iframe 仍以 dzmm.kv 为主。
建议封装统一接口：async function saveState(state) {
  if (window.dzmm?.kv?.put) {
    await window.dzmm.kv.put("game-state", state);
    return;
  }
  localStorage.setItem("game-state", JSON.stringify(state));
}
存档必须带版本号、迁移逻辑和损坏存档恢复。
不要每帧保存血量、动画、坐标等高频状态，只在战斗结束、获得奖励、切换场景等里程碑保存。
AI 功能必须有本地替代
本地剧情：使用预设文本和分支表。
本地敌人 AI：使用固定权重、规则树或随机种子。
本地图片生成：不能离线生成，使用已打包的正式素材。
本地音效：使用 Web Audio API 或项目内置音频文件。
资源全部相对路径
图片、音频、字体都放在 publish/assets/。
不依赖 CDN，避免断网后资源加载失败。
资源路径和文件名保持 ASCII。
对关键图片做预加载，加载失败时显示备用图或错误界面。
保留确定性随机
使用项目已有的 GameRandom。
离线模式同样保存 seed 和 cursor。
不要用 Math.random() 决定战斗结果，否则线上和离线无法复现。
离线包建议
包含完整 publish/。
可额外包含 README-OFFLINE.md，说明启动方式和限制。
不要把 node_modules/、.git/、Playwright 浏览器、测试报告和临时缓存放进发行包。
直接双击 publish/index.html 应能启动；如果浏览器限制 file:// 资源，应提供静态文件预览工具，但不要把服务器作为游戏运行时依赖。
主要风险

云端功能失效
AI、云存档、分享、工坊、远程图片地址都会失效。
不能把“请求失败”当成“没有数据”，否则可能覆盖玩家存档。
离线与线上状态分裂
离线修改后的存档不能自动安全合并到线上。
建议明确区分：
offline-save
cloud-save
不要在没有冲突策略时自动覆盖云端进度。
localStorage 环境差异
独立页面通常可用。
生产沙箱 iframe 可能不可用。
离线测试不能证明生产存档一定可用。
资源路径和缓存问题
file://、Workbench、线上 CDN 的相对路径解析可能不同。
每次资源或 bundle 修改都要提升 game-build。
安洁莉卡这类素材必须检查真实尺寸，避免旧缓存或旧文件名继续被引用。
浏览器兼容性
不同浏览器对 file://、音频自动播放、Web Audio、字体和 100dvh 支持不同。
BGM 必须在首次用户点击后启动。
音频失败不能阻塞游戏启动。
存档损坏
浏览器清理站点数据、隐私模式、磁盘不足都可能导致存档丢失。
建议保留两个本地槽位，并在写入前校验 JSON 和版本。
安全性降低
离线版的规则、数值和存档都暴露在前端。
玩家可以修改分数、资源和战斗结果。
离线版不要承诺排行榜、竞技公平性或防作弊。
测试覆盖不足
至少测试：
无 dzmm 启动
无网络启动
图片加载失败
音频加载失败
localStorage 被禁用
损坏存档
皮肤切换
刷新后恢复战斗或回到稳定节点
1280×720 和较小横向窗口
推荐策略

离线版定位为“完整可玩的本地单机版”，功能范围固定为：

本地战斗
本地剧情
本地素材
本地音频
本地存档
本地测试战斗
以下功能在离线模式隐藏或禁用：

AI 生成
云端存档
在线分享
创意工坊
排行榜
需要服务器校验的奖励
